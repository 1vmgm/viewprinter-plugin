# ViewPrinter review UI quality

The shared review experience defaults to **dark mode with a purple accent**. Apply that direction to the workspace, generated content galleries, controls, disclosures and linked guidance. Preserve the original appearance of videos, images and genuine app screenshots. Product-listing work remains outside this workspace.

A polished review makes the next decision obvious. The shared direction is a sharp, editorial workspace: near-black charcoal surfaces, readable light text, fine separators, small 3–5px corner radii and restrained purple for selection and primary actions. Use aligned columns and spacing to organize information. Reserve monospaced type for short IDs, counts and small navigation labels; keep sentences and hooks in a readable system sans serif. Use tabular numerals for comparable counts. Avoid washed-out text, large decorative gradients, excessive nested panels, clipped controls and a light iframe inside a dark workspace.

The overview is a working queue. Lead with next-action counts, one useful next review and a compact list with consistent identity, next-action and scheduling columns. Active, Scheduled and All content remain separate views. Status must have a text label, not color alone. Account management remains secondary. Give influencers their own recognizable identity without inventing a format for them.

Inside a review, prioritize the actual output. Keep latest/all batches, the batch selector and global playback speed easy to find. Keep common review/variant filters together. Put production status, treatment filters and bulk disclosure controls under **Review tools**. Put item review notes and provenance below the media so long agent annotations cannot push every video down the page. Preserve full hook titles, exact Copy IDs, native descriptions, source assets and costs. Do not shrink or crop the creative to achieve a denser layout.

When the user requests design research with Mobbin, inspect returned screen images before borrowing any patterns and cite their canonical Mobbin URLs when presenting them. Apply the information architecture to ViewPrinter's actual workflow instead of copying a generic dashboard. If the tool fails, state the failure; never claim the design was informed by references you could not retrieve.

Use the shared renderer and workspace assets; do not make a custom review shell for each batch or influencer. The review helpers ship with the plugin: don't edit an installed copy, which an update replaces. When a reusable control is missing, use what exists and tell the user the gap; changes to the helpers belong in the plugin's own repository. Keep one managed browser tab and stable project + format/influencer destinations.

Before handoff, inspect the real served review at desktop and narrow widths, including 390px and 320px. Check both the workspace and its iframe for overflow. Verify text contrast, visible keyboard focus, labels, useful empty/error states, long titles, filters, expandable identity/history details and archive scope. Check Copy ID, global playback speed, one playing video, and latest/all-batch navigation. Preserve exact content versions and native descriptions when changing presentation.

Use dark tokens consistently; adding a dark page background alone is not dark-mode support. Historical files can stay immutable; their surrounding history view should clearly identify them and link back to current work. Do not claim a visual review merely because the renderer built successfully. Use the supported browser/device skill for the managed tab and the shared headless checks for bulk media verification.
