# Generic creator hook → product demo

Use this as a starting recipe when a creator-led opening and product evidence fit the brief. Adapt it into project memory and, when useful, a format reference under the project’s existing content skill. Inherit that skill’s relevant shared rules; add only this format’s unique decisions instead of duplicating shared guidance or creating another skill. It carries no brand, audience, generation-model or performance assumptions.

## Coherent sequence

| Beat | Decision |
| --- | --- |
| Hook | Name a recognizable situation with enough audience/topic context to attract the intended viewer. Choose creator action, dialogue and overlay together. |
| Transition | Carry the hook's exact question or tension into the evidence; avoid a disconnected feature tour. |
| Demo / proof | Show the real feature, screen, export or outcome that answers the opening. Prepare coherent data and a short route that makes the change understandable. |
| Payoff | Resolve the opening clearly. The demo can be the ending; an extra creator reaction, brand card or CTA is optional when it serves the concept. |
| Replay | When relevant, choose a readable ending and audio boundary that lead naturally back to the opening. Do not sacrifice comprehension to manufacture a loop. |

Vary short and longer hooks according to readable copy and action, rather than padding every clip to one duration. Keep annotations near their evidence and synchronize emphasis with the words it supports. Use the project's typography, safe areas and mounting preset. Test full-frame versus mounted proof as an intentional variant, preserving legibility and honest product context.

## Capability and skill map

These are possible routes, not dependencies automatically included with ViewPrinter. Discover the installed skills/tools and read their current instructions before use; [tools](../tools.md) says how to install each one.

| Need | Available route to inspect | Keep as evidence |
| --- | --- | --- |
| Reference research and hooks | Supplied research; Scrape Creators when available and useful | Reference, date, observed structure and hook-to-proof reasoning |

| Real product proof | Installed app/browser interaction and recording guidance; Argent where available/configured; genuine product exports | Fixture scenario, route, capture, dates/totals and export source |
| Edit and motion | User/project-selected editor; installed Tesseract video/motion skills when chosen | Editable project, source timings, annotation/audio timing and final export |
| Music and loop | Project audio library or permitted sourcing under the current brief; shared [audio guidance](../audio.md) | Source, selected excerpt, trend evidence when requested, mix and end-to-start check |
| Finished-video critique | Direct viewing/listening and, when available/requested, Gemini or another video-understanding tool | Exact export/version assessed, observed issues, limits of sampling and unresolved checks |
| Review / iteration | The content-review skill's review_gallery and review_hub helpers | Existing project + format identity, batch, Copy ID, previous versions, native descriptions and provenance |
| Posting and results | content-publishing and content-learning skills | Intended account targets, exact-version receipts, dated metrics and evidence-backed learning |

Missing optional tools do not prevent reviewing existing content. If a required workflow is unavailable, identify that dependency and continue unaffected work; do not silently substitute a different deliverable. Tool names are examples of capability routes, not a claim that a package installs those tools or that every API supports every website feature.

## Project choices to save

Record audience and tone; the preferred hook/demo/payoff treatments; approved examples with IDs/versions; allowable creator, wardrobe, scene and feature variations; coherent demo-data requirements; typography and phone preset; audio direction; and required platform-native descriptions. Record generation strategies actually tried and how each did, distinguishing user preference from published results. Keep experimental variants labeled, and preserve the successful baseline for comparison.

Review the complete encoded item at intended viewing size. Verify hook readability, proof relevance, UI quality, narration/highlight timing, audio balance and ending. A silent filmstrip or successful render is not an end-to-end review. Keep unresolved checks visible. Scaling follows the user's authorization and any requested prototype checkpoint.
